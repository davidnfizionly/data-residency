# Architecture Decision Records

One line per decision that is not in `docs/PROJECT_PLAN.md`: what, why, what was rejected.

- **ADR-001 Budget without notifications.** A 5 USD monthly cost budget (credits and refunds excluded) is created only to track spend, with no alert and no e-mail subscriber. Rejected: an e-mail alert, because a cost signal was not wanted in an inbox for this project. Spend is checked by hand in Budgets and Cost Explorer instead.
- **ADR-002 S3 native state locking over a DynamoDB lock table.** Terraform >= 1.10 locks state with a lock file in the state bucket (`use_lockfile`), so one resource fewer is needed. Rejected: the DynamoDB lock table listed in the plan, now deprecated by Terraform for the S3 backend.
- **ADR-003 Backend bootstrap with local state, then migration.** The state bucket stack is applied once with local state and then migrated into the bucket it created. Rejected: creating the bucket by hand with the CLI, which would leave it outside code.
- **ADR-004 Random bucket name and partial backend config.** The state bucket uses `bucket_prefix`, and stacks read the bucket name from an ignored `*.tfbackend` file, so no account ID or bucket name is committed. Rejected: an account-ID-based name in versioned backend blocks.
- **ADR-005 Gated auto-apply.** `infra/scripts/safe-apply.sh` plans a stack, prints the plan summary, and applies the saved plan without a manual approval only when `infra/scripts/check_plan.py` confirms on the plan JSON that (a) nothing is deleted or replaced, (b) no account, organization or SCP resource is created, changed or deleted, and (c) no IAM permission uses a generic action or resource (`*` in an action, `Resource: *`, `NotAction`/`NotResource`, `Principal: *`, AWS managed policy attachments) unless its resource address is listed below as `wildcard-exception: <address>`. Policies unknown at plan time fail closed. Every other plan is approved by hand. Rejected: approving every plan by hand (slow for routine Lambda and data-plane changes) and unconditional auto-apply (no guardrail on the changes that matter for residency).
- **ADR-006 One SCP per member account, attached to the account.** Each member account gets its own guardrail with three statements: deny DynamoDB and S3 data writes outside its home region, deny writes to `data-residency-pii*` tables unless the caller's session carries `tenant_region` equal to the account's zone, and deny cross-region replication (DynamoDB replicas, S3 replication). The tenant check relies on a session tag that the router sets from the tenant record when it assumes the regional writer role. Rejected: a single region-lock SCP on the root (would affect the management account and every future account) and S3 Object Lock or table policies (do not stop a write by a principal inside the account).
- **ADR-007 Member accounts are not closed by Terraform.** `close_on_deletion = false` so a destroy cannot close an account by accident; closure or removal is decided by hand at cleanup. Rejected: automatic closure, because closed accounts stay suspended for 90 days and still count against the account quota.
- **ADR-008 Router and API in the management account, eu-west-1.** The router processes request bodies in transit, so it runs in the EEA: EU tenant data never passes through a US region, and US tenant data only transits the EU before being written in us-east-1. Rejected: a router in us-east-1 (EU PII would be processed in the US) and one router per region (moves the routing decision to the client and duplicates the stack).
- **ADR-009 Tenant registry as a versioned JSON file.** `infra/stack/tenants.json` holds each tenant's contractual `tenant_region` and routed `storage_region`; Terraform passes it to the router as an environment variable, so every routing change is a reviewed commit and shows up in the Terraform plan that the policy check reads. Rejected: a registry table edited at runtime, which would bypass review.
- **ADR-010 HTTP API with IAM (SigV4) authorization.** No API key exists to leak; callers sign requests with their AWS credentials. Rejected: a REST API with an API key (a shared secret, and a higher per-request price).
- **ADR-011 Spans exported as JSON lines to CloudWatch Logs.** The OpenTelemetry SDK runs in the router with a small exporter that writes each finished span to stdout; the Lambda log group (7-day retention) is the span store, read back with a JSON filter pattern by `GET /traces`. Rejected: X-Ray or an OTLP collector, which add a service and setup for the same evidence. Spans carry only synthetic tenant IDs, region metadata, and error messages with account IDs masked.
- **ADR-012 Misroute simulation only on direct invocation.** `simulate_storage_region` is honored only when the Lambda is invoked directly (IAM `lambda:InvokeFunction`), never through the API, so the violation demo needs AWS credentials and cannot be triggered by an API caller. Rejected: a demo flag on the public route.
- **ADR-013 Writer roles constructed by name.** IAM policies reference role, table and bucket ARNs that are known at plan time, so the auto-apply gate can read every policy; the writer roles are ordered after the router role because IAM rejects a trust policy whose principal does not exist yet.

Documented IAM wildcard exceptions: none.
